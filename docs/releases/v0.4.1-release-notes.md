Metriplane v0.4.1 adds assurance hardening to the existing reduced Truth
Recovery product. It does not broaden Metriplane beyond recorded, local,
bounded, planar, observe-only analysis.

## Atlas correctness

- Before/after comparisons require compatible rules, context, and observation
  coverage before claiming improvement.
- Recorded requirement outcomes distinguish satisfied, violated, unresolved,
  and not exercised states while retaining readability of older bundles.
- The sampled missing-state policy and its limits are explicit and tested.

## Release integrity

- A connected release-control path binds source, candidate, target,
  predecessor, qualification, approval, promotion, exact published bytes,
  reconciliation, retention, the success chain, last-known-good state, indexes,
  invalidation, and recovery.
- Fenced compare-and-swap updates reject stale and competing writers. Recovery
  reconstructs the original failed operation and preserves prior evidence.
- Tag-independent staging can prepare the canonical wheel, source distribution,
  and checksum manifest before publication. A tag or upload remains an explicit
  owner-authorized action.
- The [v0.4.1 assurance scope](v0.4.1-assurance-scope.md) retains all software
  assurance gates while recording the zero-cost single-maintainer boundary.

## Governed evidence

- A closed bidirectional traceability graph connects requirements,
  capabilities, code, tests, documentation, and rubric obligations.
- Supported command-line rows record success/failure behavior, exit status,
  text and JSON output, and output artifacts.
- Task work orders and release membership are enforced on repository changes.
- Semantic, golden, and test-obligation changes require a validated migration
  delta and the applicable independent approval.

## Compatibility and limitations

Existing product command names remain stable. Static inventory membership and
synthetic fixtures do not prove generic robotics compatibility, production
safety, physical accuracy, or external adoption. Named ManiSkill, robomimic,
ROS 2/MCAP, and MassRobotics evidence remains limited to its declared fixtures
and environments.

The exact candidate passed the governed Linux and macOS qualification on
Python 3.12 and 3.13. Clean wheel, source-distribution, TestPyPI, and production
PyPI installations passed dependency, version, doctor, demo, bundle, and
generated-regression checks. v0.4.1 does not claim a genuine independent human
signature, independently administered
production evidence stores, production external CAS/lock/LKG operation, or
multi-party privileged deployment. Those live demonstrations are explicitly
deferred by the owner to the later assurance milestones named in the assurance
scope; their software interfaces and deterministic tests remain included.

## Research boundary

The frozen v0.2.0 SoftwareX artifact and DOI `10.5281/zenodo.20736619` remain
unchanged. v0.4.1 has no DOI and makes no new research-measurement claim. The
v0.4.0, v0.4.0.post1, and v0.4.0.post2 histories remain immutable.

## Publication reconciliation incident

Production workflow `34662915868`, attempt 2, published and verified the exact
retained artifacts successfully. The broker quarantined its publication lease
after GitHub exposed an invalid future-step status before the upload job had
finished. The workflow's terminal reconciliation job therefore failed closed;
no artifact was rebuilt, renamed, retagged, or uploaded again.

Controlled recovery re-proved the exact terminal workflow, release commit and
tag, protected state generation 63, all seven rulesets, retained manifest,
public PyPI hashes, and a fresh installed-product smoke. Dry-run and execution
used proof digest
`2809cdeb185c78baf3334b87f8a02e3a00c8ffeaef590431362fcd572644e09a`.
Execution deleted only
`refs/heads/release-leases/pypi-34662915868-2`, preserved the durable recovery
record, and changed the same App check `103512565048` to
`completed/success/released`.

Provider readback found no repository hooks before GitHub Release creation, so
no automatic Zenodo archive or v0.4.1 DOI was created.
