# v0.3.0 migration and behavior changes

v0.3.0 is a usability and adoption release. It does not add ROS 2, rosbag,
MCAP, Isaac Sim, generic 3D state, robot control, safety logic, or a new research
measurement campaign.

## Primary user path

Install and run the exact release with:

```bash
python -m pip install "metriplane==0.3.0"
metriplane demo --open
```

The demo is contained in the installed package and runs without a camera, GPU,
Docker, ROS, or network access after installation. It remains usable without a
browser; omit `--open` to generate the same local files headlessly.

The bundled scenario reports six events and one incident: a required torque
driver is missing, delaying fastening by 35.0 seconds. It creates an Incident
Report, verifies the evidence bundle, and passes the generated repeatable
regression check.

## Supported Python and environments

- Python 3.12 and 3.13 are supported; Python 3.14 and later are rejected.
- Linux/Ubuntu receives the complete automated suite and release gates.
- macOS receives the bundled camera-free installed-wheel demo gate on Python
  3.12 and 3.13. That is not a claim of camera, GPU, or every integration path.
- WSL2 Ubuntu 24.04 has a bounded owner-run Python 3.12.3 installed-wheel
  validation for the camera-free and headless path. The six-event/one-incident
  demo, doctor, bundle verification, regression check, and a second headless run
  passed in that environment. Automatic browser opening is not claimed because
  the environment had no default HTML handler; omit `--open` or open the report
  path manually.
- The owner reports that the bundled camera-free demo completed from native
  Windows Command Prompt. The full environment and broader workflows were not
  validated, so native Windows is not advertised as a supported platform.

## Output replacement is explicit

Commands that create demo, run, bundle, or exported-example outputs do not
silently replace an existing path. Choose a new path or remove an old generated
output deliberately after checking its contents. This is an intentional
compatibility change for safer evidence handling.

## Validation and failure behavior

Input and process-rule validation is stricter. Malformed, contradictory,
non-finite, unsafe, incomplete, missing, or stale data now fails explicitly.
Evidence verification is fail-closed: a corrupted or incomplete bundle does
not pass, and a missing or stale run cannot create a false regression pass.

Existing integrations may need to correct formerly tolerated invalid values or
archive layouts. Do not weaken validation to preserve an invalid fixture; update
the fixture and document why its meaning remains correct.

## CLI and report wording

The beginner path is now visible in root `metriplane --help`, and
`metriplane --version` reports the installed distribution version. The demo and
active UI use the product name “Metriplane.” Compatibility-sensitive package,
command, schema, environment-variable, path, and artifact identifiers remain
lowercase `metriplane` or retain their stable historical names.

The visible HTML leads with “Incident Report.” The compatible filename remains
`cell_truth_report.html`, and “Cell Truth Report” may remain as the secondary
formal artifact name. `Atlas`, `Sentinel`, and stable command namespaces are not
renamed.

## What the result means

Metriplane analyzes recorded object state under supplied process rules. It does
not control machinery, certify safety, approve quality, infer physical accuracy,
or prove that supplied positions and zone labels match the physical world.
Deterministic replay is software repeatability for the same validated inputs,
not a physical-accuracy claim.

## Research-version boundary

v0.3.0 did not produce the frozen SoftwareX evidence or the historical TIM
measurements. The SoftwareX artifact remains v0.2.0 with DOI
`10.5281/zenodo.20736619`; the TIM evaluated software boundary remains v0.1.3.
The manuscript at `10.2139/ssrn.7166858` is cited separately. No v0.3.0 DOI
exists unless a separate archive is created later with truthful metadata.
