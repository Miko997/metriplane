# v0.5.0 single-maintainer review policy

This document records Miko Parkkinen's owner decision for Metriplane v0.5.0.
The release has a zero-euro budget and uses a single-maintainer operating model.
An external or independent human reviewer is not a mandatory v0.5.0 resource.
The absence of that reviewer is `NOT_APPLICABLE_FOR_V0_5`, never `PASS`, and no
agent, bot, CI job or GitHub App may be represented as an independent human.

This is a narrow acceptance-scope amendment for the v0.5.0 execution and release
work orders. MET-92 / MP2-030 and MET-156 / MP2-049 contain the release-specific
criteria corrected by this decision; MP2-016 supplies the common start-gate
materialization contract. It does not authorize tagging or publication, satisfy
any technical gate, or change the release candidate's readiness by itself.

## Owner decision and evidence boundary

Miko, acting as repository owner, may make the protected MP2-030 architecture
and trust-profile decision. That decision must be signed or otherwise
digest-bound through the governed owner path and must fix the attestation
envelope and format, signer/provider, trust roots, accepted identity claims,
validity and revocation policy, promotion consumer, and negative-fixture matrix.

The owner decision is authority for the selected profile only. It is distinct
from automated execution evidence and cannot be used as evidence that the
profile works, that a candidate qualified, or that publication completed.

## Mandatory v0.5.0 technical assurance

All technical implementation and release controls remain mandatory, including:

- OIDC-backed machine attestation or signature verification;
- exact subject, issuer, workflow, ref/event, commit and artifact-digest checks
  before promotion;
- missing, wrong, stale, conflicting and cross-candidate negative fixtures that
  fail closed;
- complete inherited and release-specific qualification, provenance,
  reproducibility, package-integrity and installed-product testing;
- branch protection, required CI terminals and App-broker admission;
- build-once promotion, checkpoint and lock fencing, exact-byte publication and
  provider readback;
- immutable retained evidence, reconciliation, chain/LKG/index updates,
  invalidation, interruption and recovery controls; and
- audited operator, infrastructure-owner and publisher actions wherever those
  live effects are applicable.

No technical verdict becomes `PASS` from this owner decision. Missing,
incomplete, stale, mismatched or unverifiable machine evidence remains
`BLOCKED_NOT_READY`.

## Human-review classification

For v0.5.0 only, the following requirements are removed from its start and
release gates:

- an independent or non-author human candidate/qualification approval;
- a second-human READY review;
- `backup_non_author_reviewer`; and
- a reviewer key or reviewer signature whose sole purpose is proving human
  independence.

The MP2-049 work order must materialize the independent-human action as
`NOT_APPLICABLE`, with this policy as its governing reference. It must retain
the publisher, operator and infrastructure roles, their applicable backups,
and all cryptographic machine attestations and verification.

MP2-016 work-order validation must apply the same classification: no external
human supplies the v0.5.0 `READY` decision. `READY` is an automated result over
a genuine owner-to-executor delegation and all other exact work-order inputs.
The owner grant is authority, not automated execution evidence, and neither
Codex nor any other automated actor is a human reviewer.

Organizational separation of duties remains in the later assurance milestones
that genuinely require it. In particular, MP2-207, MP2-210, MP2-223 and MP2-225
retain their independent-human or non-maintainer requirements. This policy does
not amend those task rows.

## Release-readiness boundary

The policy decision is `OWNER_APPROVED`, while the v0.5.0 release remains
`BLOCKED_NOT_READY` until every other implementation dependency and technical
gate has passed for one exact candidate. Approval of this document is not a
release authorization.
