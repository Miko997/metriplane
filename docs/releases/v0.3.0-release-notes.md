Metriplane v0.3.0 adds a bundled, camera-free demo that turns a recorded
missing-tool incident into an incident report, verified evidence bundle, and
repeatable regression check.

## Install and run

Install the verified production package with:

```bash
python -m pip install "metriplane==0.3.0"
metriplane demo --open
```

The demo runs offline after package installation and does not require a camera,
GPU, Docker, or ROS. On a headless or SSH system, run `metriplane demo` without
`--open` and open the printed report path later.

## Bundled result

The recorded assembly run contains a missing required torque driver. The
fastening step is delayed by 35.0 seconds.

- incident timeline: six events;
- incident report: one incident;
- evidence bundle: verified;
- repeatable regression check: passed;
- local HTML Incident Report: generated.

The generated check can be run again after software or process-rule changes.

## Supported environments

- Linux/Ubuntu: complete suite and release gates on Python 3.12 and 3.13.
- macOS: bundled camera-free installed-wheel demo on Python 3.12 and 3.13.
- WSL2 Ubuntu 24.04: bounded owner-run Python 3.12.3 installed-wheel and
  headless validation. The install-to-report path completed in 7 seconds, but
  automatic browser opening is not claimed because no default HTML handler was
  available; users can omit `--open` or open the report path manually.
- Native Windows: the owner reports that the bundled camera-free demo completed
  from Windows Command Prompt. Broader native-Windows workflows are not covered
  by the release matrix and are not advertised as supported.

Camera, GPU, ROS 2, USD/Isaac, and other optional or repository-only paths have
their own narrower support status. They are not required for this release's
two-command demo.

## Hardening in this release

- explicit no-clobber behavior for generated outputs;
- stricter state, process-rule, and persisted-configuration validation;
- fail-closed archive and evidence verification;
- protection against stale or missing outputs producing a regression pass;
- transactional publication of run, bundle, and privacy-export outputs;
- clearer propagation of replay, live-runtime, launcher, and runner failures;
- clean installed-wheel checks outside the source repository;
- independent source-distribution installation and exact artifact hashing in
  the publication workflow.

## User-facing changes

- A complete package-contained example is available through `metriplane demo`.
- Root help puts `demo` and `doctor` first and describes commands in ordinary
  language.
- `metriplane --version` matches package and distribution metadata.
- The visible report leads with “Incident Report”; its stable
  `cell_truth_report.html` filename remains compatible.
- Active product text uses “Metriplane,” while compatibility-sensitive lowercase
  identifiers and frozen historical evidence are unchanged.
- Example inputs can be exported for the documented recorded-run tutorial.

See the [migration and behavior-change note](v0.3.0-migration.md) for details.

## Known limitations

Metriplane expects timestamped, already-estimated object state and process rules
for a bounded workcell. v0.3.0 does not provide a generic raw-video, rosbag,
rosbag2, or MCAP importer. It does not add generic 3D state or native Windows
support. Positions alone do not infer zone labels.

Metriplane is observe-only. It does not control a robot or machine, certify
safety, approve quality release, or prove physical measurement accuracy.

No unfamiliar-user comprehension study was completed before release. The
zero-tester record remains pending, and the documented protocol is retained for
post-release adoption follow-up; no passing human-validation claim is made.
