# ManiSkill PickCube adapter preflight audit

Status: **GO — owner decisions implemented; adapter and portable fixtures
frozen; three clean conversions demonstrated.**

This note records the source, architecture, and claim-safety preflight for one
official ManiSkill `PickCube-v1` motion-planning trajectory. It is deliberately
written before adapter implementation. A portable fixture must not be generated
until the unresolved contract questions below have an explicit disposition.

This document began as a pre-implementation PAUSE record. Its original
forward-looking language, unresolved-question analysis, and PAUSE recommendation
remain below as decision history. Section 13 records the later implementation
without rewriting that history.

## Owner decisions — 2026-08-11

The original PAUSE analysis in this document is preserved as the decision
history. The owner resolved its implementation gates as follows:

1. The fixture is position-only. Complete source quaternion, yaw, roll, pitch,
   and source Z are intentionally excluded from normalized evaluation. No
   orientation field, object `extra`, FrameStateModel change, or External Source
   Contract change is authorized.
2. The complete target polygon is a Layer-C operator rule. Its frozen center is
   the audited projected goal XY (`0.026815735`, `-0.001981318` metres), its
   square half-extent is `0.010000000` metres, and its boundary policy is
   inclusive. The source goal remains an inert disclosed source/adapter fact,
   not a runtime derivation of the polygon.
3. The cube is modeled as the expected `material` and `robot_tcp_1` as the
   genuinely required `tool`. The approved Metriplane-authored planar experiment
   compares the same normalized state under relative missing-tool waits of
   `0.20` seconds (incident) and `0.30` seconds (control). These values begin
   when the cube is present and the TCP is missing; they are not absolute
   trajectory timestamps.
4. Generic, source-neutral corrections to Atlas output wording and durable path
   handling are authorized, provided they do not change schemas, process or
   incident semantics, frozen research evidence, or add source-specific logic.
5. Raw HDF5/JSON and simulator assets remain referenced and excluded. The
   independently authored adapter is MIT-licensed, while portable source-derived
   fixture data receives separate Apache-2.0 attribution and a modified-data
   notice through REUSE-compliant metadata.

The source project, release, dataset revision, task, episode `0`, group
`traj_0`, 74 transitions, 75 stored states, 50-step provenance-only horizon,
and every recorded source hash remain frozen. Implementation resumes on
`agent/maniskill-pickcube-fixture` without changing FrameStateModel 1.0,
External Source Contract v1, or Atlas process semantics.

## 4. Proposed adapter boundary

The smallest acceptable layout is:

```text
adapters/maniskill_pickcube/
  pyproject.toml
  uv.lock
  README.md
  src/maniskill_pickcube/
  tests/
```

All imports of ManiSkill, SAPIEN, Torch, and h5py would remain under that
directory. The root Metriplane wheel already packages only the ordinary project
packages, so this adapter can remain outside the normal runtime distribution.
The adapter would have its own complete dependency lock and an immutable Linux
conversion-environment identity. The portable fixture would contain normalized
JSON/YAML/CSV only and would not invoke the adapter.

No plugin system, generic HDF5 importer, source-specific Atlas branch, or
ManiSkill-aware generic validator is proposed.

## 5. Proposed restoration mechanism

The audited method uses the public v3.0.1 state API, not action integration:

1. Construct one `PickCube-v1` CPU environment from the recorded metadata.
2. Assert a 20 Hz control frequency and 0.05 s control period.
3. Convert the HDF5 dictionary-of-arrays into per-state dictionaries with the
   official trajectory utility.
4. Restore each of the 75 stored states independently with
   `env.unwrapped.set_state_dict(state_i)`.
5. Read `cube.pose`, `goal_site.pose`, and, only if the process rule requires a
   genuine tool, `agent.tcp_pose` through named APIs.

The CPU pilot required a software Vulkan device even though it did not render or
create images, because v3.0.1's PickCube builder constructs render-material
objects during scene construction. This is a conversion-environment concern;
the finished portable fixture must not require Vulkan.

The pilot restored every state without action replay. Named cube and goal poses
matched their corresponding stored `[position, quaternion]` values with maximum
absolute error `0.0`.

Three fresh environment constructions and complete 75-state restorations
produced the same little-endian float32 pose-stream SHA-256 each time:

```text
1c2fe261f0bb2190683900e5b751c9416a18f13b6a6485c45969809bd48860d2
```

This is pilot restoration evidence, not final fixture determinism evidence.

## 7. Clock derivation

Pinned ManiSkill defaults are 100 Hz simulation and 20 Hz control, and PickCube
does not override them. The proposed authoritative clock is:

```text
ts_sim_ns(i) = i * 50_000_000
ts(i) = i * 0.05 seconds
```

Frame zero is the stored reset state before the first transition. Frame 74 is
at 3.70 s. All 74 transitions and all 75 stored states are retained. The
registered 50-step RL horizon is source metadata only; it is neither a deadline
nor a truncation instruction.

## 8. Projection and orientation

The position-only projection is source world X to normalized X and source world
Y to normalized Y, in metres, with no translation, rotation, scale, or axis
swap. Normalized Z would be exactly zero and source Z would be declared lost.
Pinned documentation establishes Z-up and the rotation implementation is
consistent with a right-handed world frame, but it does not state “right-handed”
verbatim. A final report must label handedness as an implementation-supported
inference rather than a quoted source fact and retain a compatibility assertion.

The source pose layout is `[x, y, z, w, x, y, z]`. For audit purposes, the
official quaternion-to-matrix utility was used and yaw was calculated as
`atan2(R[1,0], R[0,0])`. Across the selected episode:

- minimum projected source X-axis norm: `0.9999962449`;
- yaw range: `1.9294760` to `1.9320796` radians.

Yaw is therefore numerically well-defined, but **FrameStateModel 1.0 has no
orientation or yaw field**, and the external profile prohibits using
`ObjectStateModel.extra`; the contract's closed normalized-field vocabulary also
has no orientation field. Emitting yaw would require a forbidden schema change
or a contract violation. Dropping the entire quaternion would be deterministic
and claim-safe, but it would not satisfy a literal requirement to emit normalized
yaw. This requires an explicit disposition before implementation.

Other declared losses would include source Z, roll, pitch, linear/angular
velocity, contact and grasp state, robot joint state, reward, success, failure,
termination, truncation, and task-evaluation annotations.

## 9. Planar fit and provisional process experiment

Episode 0 contains a non-degenerate XY transit:

- cube start-to-goal XY distance: approximately `0.0620807 m`;
- cube end-to-goal XY distance: approximately `0.00662469 m`;
- cube XY displacement: approximately `0.0584631 m`;
- cube Z range: approximately `0.0200 m` to `0.2862 m`.

The vertical displacement is large and must be prominent in every claim
limitation. The only honest process wording is a Metriplane-authored planar
compatibility rule such as “cube and robot TCP enter a declared target XY
region.” It is not PickCube success, 3D placement, or grasp evaluation.

In a non-final pilot, a square with 0.01 m half-extent centered on the recorded
goal XY contained the cube from frame 66 and the TCP from frame 71; both were
inside for frames 71 through 74. This makes an existing-rule experiment possible:

- incident candidate: require `robot_tcp_1` first and `cube_1` second in the
  target region, with an operator deadline before 3.55 s;
- control candidate: the same normalized session and geometry, with an operator
  deadline greater than 3.50 s so the step completes at frame 71 before a delay.

These are pilot thresholds, not frozen or independently predefined rules. The
TCP is deliberately first because Atlas currently names every delay incident
`missing_tool_caused_delay`; a cube-only arrival rule would make that result
semantically false.

## 11. Unresolved questions and generic defects

### Blocking contract questions

1. **Orientation:** may this bounded fixture intentionally omit all orientation,
   or is normalized yaw mandatory? The latter is impossible without changing a
   frozen generic model or violating its profile.
2. **Trust layer for target geometry:** External Source Contract v1 puts all
   zones in Layer C and the hashed domain pack. The requested field map instead
   classifies a goal-derived target center as Layer 2. The contract cannot split
   one workspace polygon into a Layer-2 center and Layer-3 half-extent.
3. **Handedness evidence wording:** the pinned coordinate documentation is Z-up
   and the official rotation code is right-hand consistent, but it does not make
   a direct prose handedness declaration. The final provenance must distinguish
   this inference from a directly stated source fact.

### Fixable generic defects, not adapter workarounds

1. Atlas reports currently say results come from “replayed calibrated planar
   state” and depend on “tracked or tagged objects.” Evidence limitations say
   “calibrated planar state streams” and “tracked/tagged assets.” The dashboard
   and shared limitation tokens repeat the same camera/tracking assumptions.
   Those statements are false for restored simulator state. A source-neutral
   generic wording change is required before a claim-safe external fixture can
   be published.
2. `atlas_manifest.json` persists operational session and domain-pack paths. A
   strict no-local-path release gate needs a generic path-neutral representation.
   The dashboard and connector snapshot embed that manifest, and the USDA
   exporter currently reopens the recorded machine-local session path, so this
   must be corrected coherently rather than redacted in one adapter output.
3. Atlas has no generic arrival-deadline incident. Its only delay incident is
   `missing_tool_caused_delay`. The TCP-first rule above is viable but narrow; a
   cube-only rule is not claim-safe.

The first two defects may be corrected generically without adding a single
ManiSkill condition. They must not be hidden by adapter-specific rewriting.

## 12. Recommendation

**PAUSE final implementation.** Source identity, structural selection, state
restoration, timing, deterministic pilot extraction, and a bounded planar event
are all viable. The task should resume only after the project owner decides:

1. that complete orientation discard is acceptable for this position-only
   FrameStateModel 1.0 fixture;
2. that the target polygon is wholly an operator-configured Layer-C rule, with
   the source goal used only as disclosed pilot rationale, or provides another
   contract-preserving trust-layer interpretation;
3. that a genuine TCP-plus-cube rule is an acceptable bounded use of the current
   `missing_tool_caused_delay` semantics; and
4. that the two source-neutral generic output corrections may be made in this
   branch without changing the external contract or Atlas process semantics.

Until those decisions are explicit, writing the adapter or tuning final
thresholds would risk encoding an answer the frozen interfaces cannot represent
honestly.

### Implemented adapter and normalization boundary

The isolated adapter is under `adapters/maniskill_pickcube/` with its own
project metadata and dependency lock. ManiSkill, SAPIEN, Torch, h5py, Hugging
Face acquisition code, and conversion-only Vulkan requirements remain outside
the ordinary Metriplane runtime. The portable fixtures are under
`examples/external_sources/maniskill_pickcube/` and require none of those

All 75 stored states are restored independently. The adapter never steps the
environment or integrates actions. Every normalized frame contains exactly
`cube_1` as a `material` and `robot_tcp_1` as a `tool`; the goal marker and full

is `0.0`, and the authoritative clock is

resampling, carry-forward, confidence, or normalized source event.

The complete source quaternion exists and audit yaw was numerically
well-defined. The implemented position-only fixture nevertheless excludes
source Z, quaternion, yaw, roll, and pitch from normalized evaluation. None is
hidden in object `extra` or another Atlas input. The result is limited to
bounded XY occupancy and timing; it does not evaluate 3D placement,
orientation, grasp state, or official PickCube success.

The complete target polygon is read from the frozen configuration and emitted

- square half-extent: `0.010000000` metres;

### Implemented rights boundary and REUSE scope

The independently authored adapter subtree is MIT-licensed. The public fixture
subtree is treated separately as Apache-2.0 modified/derived data, with raw
source bytes and simulator assets absent. `LICENSES/MIT.txt`,
`LICENSES/Apache-2.0.txt`, and `.reuse/dep5` express this distinction; the
fixture stanza uses `NOASSERTION` rather than inventing an upstream copyright
holder. The fixture README and manifests carry the source citations and
modified-data notice.

REUSE compliance for the new adapter and fixture paths is scoped separately
from the repository-wide baseline. The audited global baseline already failed
REUSE 3.3 before this fixture work: 1,068 files were scanned, 642 had copyright
information, and 641 had licensing information; broad pre-existing and frozen
evidence material lacked complete metadata. No blanket license was applied to
that material, and a clean repository-wide `reuse lint` result is not claimed.
The scoped treatment must not be described as relicensing the repository or its
frozen evidence.
