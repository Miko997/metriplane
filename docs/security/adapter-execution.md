# Adapter execution boundary

External acquisition and normalization are two separate authority stages.

Remote acquisition is admitted only when repository, immutable revision, artifact path, byte
size, and SHA-256 match one unique checked-in declaration. A pre-downloaded artifact remains an
offline input and is still checked by exact size and digest before extraction.

The canonical `metriplane external normalize` command verifies the exact local artifact against a
reviewed allowlist before it invokes the shared external-source sandbox. The sandbox refuses
privileged execution, opens fixed `/usr/bin/bwrap` and Python identities from root-controlled,
non-writable files, discards the inherited environment, permits no caller-supplied environment
entries, unshares network and process namespaces, drops capabilities, exposes input through a
retained read-only directory descriptor inside an isolated root, and requires the adapter to emit
one plain USTAR stream on stdout. The parent copies fixed-size chunks into one anonymous memfd and
kills the adapter before accepting a byte beyond the governed archive bound, so adapter output
cannot consume host filesystem inodes or unbounded bytes. An architecture-checked seccomp filter rejects
sockets, process creation, namespace
creation and namespace entry (including the x86 x32 ABI); nested user namespaces are disabled.
The adapter is therefore the only admitted process. Wall time, CPU, virtual address space, open
files, individual and aggregate generated bytes, file count, tree depth, and captured output are
finite. While hashing, verification copies the exact artifact bytes into a private memfd and adds
kernel seals that prohibit writing, growing, shrinking, or adding weaker future seals. Bubblewrap
copies only that sealed snapshot into the declared read-only input path, so neither pathname
substitution nor in-place source mutation can change the admitted bytes.

After the adapter stops, the parent parses the uncompressed archive, rejects absolute or
non-canonical paths, duplicate names, links, special files, file/parent conflicts, excessive depth,
member count, individual size or aggregate size, and only then extracts regular bytes into an empty
retained publication stage. Canonical fixture validation reads the retained staging descriptor,
verifies that its identity did not change, and publishes it with Linux
`renameat2(RENAME_NOREPLACE)` relative to a retained parent descriptor. A concurrently created
target, path substitution, changed stage identity, failed validator, quota violation, timeout, or
non-zero adapter exit never yields a successful publication. Cleanup removes only names that still
identify the retained stage; it does not delete an attacker-substituted pathname.

The boundary fails closed when bubblewrap or required kernel isolation is unavailable. It does
not treat containers as a substitute for source identity or canonical output validation.
